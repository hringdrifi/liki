# Android BLE HIDの実装と検証記録

現在のmainには、`BluetoothGattServer` によるHID over GATT（HOGP）送信と、
`BluetoothHidDevice` によるClassic送信の両方があります。この文書はBLE方式を対象にします。
BLE選択時はClassicのHID Deviceプロファイルを登録せず、外付けキーボード・マウスの入力を中継できます。
Bluetooth接続したZMK Studio対応キーボードの配列取得・割り当て編集にも対応しています。
AndroidではPCへのBLE接続・通常画面からの入力送信と、外付けキーボード・マウスの中継について実機確認記録があります。
操作手順は[使い方ガイド](usage.md)、ビルドは[ビルドと導入手順](build-and-install.md)を参照してください。

## 試し方

1. BLE Peripheralに対応するAndroid端末を使います。Android 9以上でも、端末やOSによっては利用できません。
2. 現行版のAPKをインストールします。開発ビルドではMetroにも接続します。
   Expo Goは使用できません。ネイティブ機能の追加・変更を試す場合は再ビルドが必要です。
3. Bluetooth接続・公開権限を許可し、接続方式を「Bluetooth LE (BLE)」にして「BLEペアリング待機」を押します。
4. PCのBluetooth設定から、Android端末のBluetooth名を選んで接続します。
   アプリからPCへの接続開始や接続先の選択は行いません。
5. 「BLE HID接続中」になったら操作画面からキー・マウス入力を試します。

Windowsのビルド例（JDK 21、Android SDKとnpm依存関係の準備後）:

```powershell
npx expo prebuild --platform android --no-install
$env:JAVA_HOME = 'C:\Program Files\Microsoft\jdk-21.0.12.101-hotspot'
$env:ANDROID_HOME = 'C:\Users\ito\AppData\Local\Android\Sdk'
Push-Location android
.\gradlew.bat :app:assembleDebug
Pop-Location
npm start -- --lan --port 8081
```

初回や従来のClassic HID版からの切り替え時に、PCに古いサービス情報が残っている場合は、
そのPCとのペアリングを双方で解除してから再ペアリングします。
既存のペアリング情報をアプリが自動削除することはありません。

## キーボード・マウスを中継

PCと接続した後、右端メニューの「入力方法」で「外部キーボード・マウス」を選びます。
スマホへBluetoothまたはUSBで接続したキーボード・マウスを対象にし、ZMKや特定のメーカーには限定しません。
接続された物理入力デバイスの名前を表示します。

通常のキーボード表示は中継画面へ切り替わります。前のレイアウトと保存データは保持し、
右端メニューの「入力方法」で「仮想キーボード・タッチパッド」を選ぶと中継を終了します。
モードの選択は保存し、再起動後もPCに接続すると復元します。

押下・解放、左右の修飾キー、同時押し、対応するメディアキーを転送します。
通常キーは最大6キーの同時押しです。超過時はErrorRollOverを送信し、6キー以下に戻ると復帰します。
PC側でキーリピートを処理するため、Android側のリピートイベントは再送しません。
文字列への変換やIME経由の入力は行いません。OSが予約・消費するキーや、未対応のキーは転送できません。

マウスの相対移動、左・右・中ボタン、ドラッグ、縦ホイールを転送します。横スクロールと追加ボタンは対象外です。
Androidではポインターキャプチャを使うため、中継中のメニュー操作はスマホのタッチで行います。
細かい移動量は蓄積し、HIDのレポート範囲を超える移動は分割して送信します。

Likiが前面にあり中継画面を表示している間だけ入力を扱います。
メニュー・ダイアログ・設定を開いたとき、フォーカスを失ったとき、入力デバイスやPCが切断されたときは
キーとマウスボタンの押下状態を解放します。入力の履歴は保存しません。

iOSはGameControllerのGCKeyboardとGCMouseを使います。マウス対応版のネイティブビルドは成功、マウス転送の実機動作は未検証です。
新しいネイティブビルドが必要で、iOSはキーボードを1つにまとめて通知します。
iOSでのメディアキー取得は保証しません。

## 実装範囲

- HID Service、Battery Service、Device Information Serviceを公開します。
- キーボード、3ボタンマウスと縦スクロール、Consumer Controlを送信します。
- Report ProtocolとBoot Protocolに対応します。Boot Protocolではメディアキーを送信しません。
- 入力レポート、LED出力、Protocol Mode、Control Point、購読設定へのアクセスは暗号化を要求します。
- 接続先は1台です。入力Characteristicの購読後に操作画面へ移ります。
- ペアリング済みPCの通知購読設定（CCCD）はPCごとに保存し、切断・アプリ再起動後に復元します。
  ペアリング解除時は削除します。復元した通知もBLEリンクの暗号化を確認するまで送信しません。
  Android 16以上では暗号化状態の通知を使い、それ以前では暗号化を要求する属性へのアクセスで確認します。
  旧ビルドで保存されなかった購読設定は復元できません。PCが購読を書き込んだ後から保存されます。
  この修正後も、アプリ再起動後に公開中のまま再接続されない症状は残っています。
- 通知はコールバックを待って順に送信し、送信失敗・キュー超過・タイムアウトは切断して画面に表示します。
- バックグラウンド移行時に入力解放を送信します。バックグラウンドでの継続動作は保証しません。
- PCが切断した場合は公開を再開します。「切断」を押した場合は公開も停止します。
- AndroidのJSリロードではGATT接続と公開状態を維持し、入力の押下状態だけを解放します。
  新しいJSランタイムへ画面・イベント通知を付け替え、古いランタイムの遅延終了処理では接続を閉じません。
  Activityを明示終了した場合やアプリのプロセス終了時は接続も終了します。
- PnP IDは実験用のBluetooth SIG vendor ID `0xffff` を使います。製品用の識別情報ではありません。

## 実機で確認する項目

以下は端末・接続先ごとの確認項目です。既存の検証結果は後述し、すべて未確認という意味ではありません。

- PCからの検出、ペアリング、暗号化、HID認識、各入力レポートの購読。
- 英数字、Shift/Ctrlなどの修飾キー、メディアキー、Caps LockのLED出力受付。
- ポインター、クリック、ドラッグ、スクロール。
- PC側切断後の再接続、アプリ側切断、Bluetoothのオフ・オン、画面の回転・再生成。
- 入力中のバックグラウンド移行で押しっぱなしが残らないこと。
- ZMKをAndroidのBluetoothキーボードとして接続したまま、PCへのBLE HID送信ができること。
  さらに中継モードで文字キー・修飾キー・同時押し・長押し・メディアキーの入力を確認します。

参考: [Android BluetoothGattServer API](https://developer.android.com/reference/android/bluetooth/BluetoothGattServer)

## BLE導入時の検証記録

以下のテスト件数・lint結果・再接続の調査内容は当時の記録です。現行版のチェック結果を示すものではありません。

- `:app:assembleDebug`: 成功。出力は `android/app/build/outputs/apk/debug/app-debug.apk`。
- `npm run typecheck`: 成功。
- `npm test`: 中継モードとAndroidプラグインの回帰テストを含む26件。BLE通信そのものを検証するテストではありません。
- `:liki-hid:testDebugUnitTest`: 押下状態、複数キーボード、ロールオーバー、メディアキー、キーコード変換の5件と、
  リロード時の接続保持・古いランタイムの終了・Activity終了・二重終了に関する4件、
  購読設定の再生成後の復元・PC間の分離・購読解除・ペアリング解除に関する4件、
  マウスの移動分割・端数蓄積・複数機器のボタン保持・解放に関する4件が成功。
- `npm run lint` と同じ `expo lint`: 成功（既定の対象は `src` / `app` / `components`）。
- 追加の `App.tsx` 直接lint: 既存の `react-hooks/refs` エラーが残っています。
  既存のモデル参照方式に関するエラーと警告が残っています。
  `plugins/with-liki.js` の直接lintは成功。
- 通常画面からのBLE HID送信と、Androidのキーボード・マウスの実入力中継はユーザーが動作確認済みです。
  マウスは移動・左/右/中クリック・ドラッグ・縦スクロールを確認済み。iOSマウス版はビルド・同梱資産検証まで成功し、実機入力は未確認です。
- アプリ再起動後の再接続は未解決です。Androidの公開成功と公開継続を確認し、
  Windowsでも既存登録と同じアドレスの広告を受信しましたが、PCからの新しい接続イベントは届きませんでした。
  Windows上のLikiのHIDデバイスは存在しない状態となり、ペアリングを保持したGATTサービス再取得も
  `Unreachable` でした。終了時のサービス削除とWindows側の接続管理のどちらが原因かは未確定です。
- 終了操作は最近使ったアプリ一覧からのスワイプです。端末の終了履歴に `SwipeUpClean` が記録され、
  そのプロセス終了の約0.7秒後にWindowsのHIDデバイスが削除された時刻が対応しています。
  AndroidのGATT実装はアプリのBinder終了時にサーバーを登録解除し、その際にサービスも削除します。
  再公開後の再接続失敗はPCのBluetoothオフ・オンでも解消していません。
  スワイプ終了時のサービス消失までは確認済みですが、その後Windowsが再接続できない原因は未確定です。
- ユーザーの追加検証では、WindowsのBluetoothをオフにしてLikiを再起動し、
  HIDサービスが準備された後でWindowsのBluetoothをオンにすると再接続できました。
  一方、WindowsがオンのままLikiを再起動すると再接続できませんでした。
  HIDサービスのない期間にWindowsが接続・探索することが失敗の条件と考えられます。
  WindowsがADV_INDを探索しなくなるかどうかは無線トレースで未確認です。

## Windowsの再接続サポート

任意の[Windows用再接続サポートツール](../tools/windows-reconnect/README.md)を同梱しています。
ペアリング済み端末へのBLE接続要求を維持し、Liki再起動後の再接続を支援します。
入力の受信・中継やHIDレポートの購読、ペアリングの作成・削除は行いません。
ツールの「接続済み」はBLE接続の状態です。実際のキー・マウス入力は別途確認してください。
